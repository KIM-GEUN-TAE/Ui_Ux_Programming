# 겜뽑기

취향만 고르면 오늘 할 게임을 뽑아드립니다.

게임은 많은데 오늘 뭘 할지 정하지 못해 시간을 보내는 게이머를 위한 서비스입니다.
장르·분위기·플레이 시간 같은 취향을 고르면 조건에 맞는 게임 중 하나를 추첨해서 바로 정해줍니다.

## UX 계획

| 항목 | 내용 |
| --- | --- |
| 사용자 | 게임은 많은데 오늘 뭘 할지 정하지 못해 시간을 보내는 게이머 |
| 목적 | 내 취향에 맞는 게임을 고민 없이 빠르게 하나 정한다 |
| 핵심 행동 | 취향 키워드를 입력하고 게임 뽑기 버튼을 누른다 |
| 정보 순서 | 서비스 소개 → 주요 기능 → 이용 방법 → 게임 뽑기 |

## 구현하면서 바꾼 부분과 이유

### 1. 마지막 영역 `#subscribe` → `#pick`(게임 뽑기)

예제 서비스(캠퍼스 마감 알림)의 핵심 행동은 "이메일로 알림 신청"이라 `#subscribe`였지만,
겜뽑기의 핵심 행동은 "취향을 입력하고 게임을 뽑는 것"입니다.
nav 메뉴 이름·section id·h2 제목·버튼 문구가 모두 같은 말이어야 사용자가 이동 결과를
예상할 수 있으므로, 영역 이름을 **게임 뽑기(`#pick`)** 로 통일했습니다.

### 2. 입력 칸을 이메일 대신 취향 키워드로 변경

`type="email"` 입력은 이 서비스에서 사용자가 실제로 해야 하는 행동과 맞지 않습니다.
2주차 범위인 "입력 한 칸 + 버튼"은 유지하면서, 입력 목적을 **취향 키워드**(`type="text"`)로 바꾸고
placeholder에 "예: 혼자, 힐링, 30분"처럼 작성 예시를 넣었습니다.
장르·분위기·플레이 시간을 각각 고르는 여러 입력 항목(`select`, 체크박스 등)은
9주차 폼 실습에서 확장할 예정입니다.

### 3. 주요 기능 순서 · `ul` 선택 이유

취향 고르기 → 랜덤 뽑기 → 뽑은 게임 기록 순으로 적었지만, 순서를 바꿔도 각 기능의 의미가
유지되므로 `ul`(순서 없는 목록)을 사용했습니다.
반대로 이용 방법은 "취향 고르기 → 뽑기 버튼 → 결과 확인"처럼 순서가 바뀌면 이용이 불가능하므로
`ol`(순서 있는 목록)로 작성했습니다.

### 4. 이미지 alt

이미지가 "무엇을 보여주는지"가 아니라 이 위치에서 **전달하려는 의미**를 쓰도록
"혼자·힐링·30분 취향 태그를 고른 뒤 오늘의 게임 추첨 결과 카드가 표시된 겜뽑기 화면"으로 작성했습니다.
현재 이미지는 서비스 화면 시안을 표현한 임시 이미지이며, 이후 실제 화면으로 교체할 예정입니다.

## 3주차 · CSS 수정 기록

### 수정한 내용

주요 기능 세 개를 감싸는 `.feature-list`에 `display: flex`와 `gap: 20px`을 적용하고,
각 `.feature-card`에 `flex: 1` · `padding: 24px` · `border` · `background-color`를 주었습니다.

### 화면에서 달라진 점

세로로 길게 나열되던 기능 목록이 같은 너비의 카드 세 개로 한 줄에 놓이고,
카드 사이 간격이 일정해졌습니다. 카드마다 연한 배경과 테두리가 생겨 하나의 정보 단위로 보입니다.

### 사용자에게 필요한 이유

세 기능이 같은 종류의 정보라는 것을 한눈에 인식하고 서로 비교하기 쉬워집니다.
목록이 흩어져 보이면 각 항목을 따로 읽어야 하지만, 카드 그룹으로 묶이면 "이 서비스가 하는 일 세 가지"로 바로 읽힙니다.

## 4주차 · 반응형 수정 기록

### 확인한 문제

390px에서 3주차 가로 배치가 그대로 남아 서비스 소개 글이 한 글자씩 끊기고, 이미지가 카드 밖으로 튀어나왔습니다.
기능 카드 세 장도 한 줄에 눌려 글이 한두 글자씩 끊겼고, 메뉴 링크는 두 줄로 쪼개졌습니다.
769px에서도 서비스 소개 글이 이미지 옆에 좁게 남아 몇 글자마다 줄이 바뀌었습니다.

### 수정한 내용

`.site-header` · `main` · `.site-footer`에 `width: 100%`를 추가하고, 이미지는 `width: 100%` · `max-width: 420px`로 바꿔 부모 너비에 맞춰 줄어들게 했습니다.
기능 카드 목록 `.feature-list`는 Flexbox 대신 `repeat(auto-fit, minmax(260px, 1fr))` Grid로 바꾸고, 메뉴와 서비스 소개 영역에는 `flex-wrap: wrap`을 적용했습니다.
`@media (max-width: 768px)`에서는 메뉴 · 기능 카드 · 취향 입력창과 버튼을 한 열로 배치하고, 제목 크기와 카드 여백을 줄였습니다.
viewport 메타 태그는 1주차부터 `charset` 바로 아래에 있어 중복해서 추가하지 않았습니다.

### 달라진 점

1100px에서는 기능 카드가 세 열, 769px에서는 두 열로 자동 배치되고 서비스 소개 이미지가 글 아래로 내려갑니다.
768px부터는 메뉴 · 카드 · 폼이 한 열로 바뀌어, 390px에서도 가로 스크롤이나 잘림 없이 소개 글을 읽고 화면 너비만큼 넓어진 버튼으로 게임을 뽑을 수 있습니다.

## 6주차 · 이벤트와 동적 UI 기록

### 구현한 이벤트와 화면 변화

| 이벤트 | 요소 | 사용자 행동 | 화면 변화 |
| --- | --- | --- | --- |
| `click` | `#themeButton` | 화면 테마 버튼 클릭 | `body`에 `dark` 클래스가 붙었다 빠지며 배경 · 글자 색이 바뀌고, 버튼 문구가 "밝은 테마로 바꾸기"와 "어두운 테마로 바꾸기"로 번갈아 바뀜 |
| `input` | `#nickname` | 닉네임 입력 · 삭제 | 글자를 쓰거나 지울 때마다 `#nicknameCount`가 `0 / 10` → `3 / 10`처럼 바뀌고, 뽑기 결과 문구 앞에 "닉네임님,"이 붙음 |
| `change` | `#allGamesCheck` | "취향 상관없이 전체 게임에서 뽑기" 체크 · 해제 | 안내 문구가 바뀌고 `is-checked` 클래스로 초록 배경이 생기며, 취향 입력창이 `disabled`로 바뀜 (해제하면 모두 원래대로) |
| `click` | `.tab` 3개 | 주요 기능 탭 클릭 | 누른 탭에만 `is-active` · `aria-selected="true"`가 붙고, `data-target`으로 연결된 패널 하나만 보임 |
| `submit` | `#pick-form` | 게임 뽑기 | 후보 수와 뽑은 게임을 초록 문구로 보여 주고 버튼이 "다시 뽑기"로 바뀜. 빈 칸이거나 후보가 없으면 빨간 오류 문구 |

주요 기능 카드 세 개는 탭 세 개(취향 고르기 · 랜덤 뽑기 · 뽑은 게임 기록)로 바꾸고, 취향 고르기 탭에 입력할 수 있는 키워드(인원 · 분위기 · 시간 · 장르)를 정리했습니다.

### 5주차 피드백 반영

5주차에는 입력한 취향과 상관없이 전체 목록에서 뽑아서, "조건에 맞는 게임 중 하나를 뽑는다"는 안내와 실제 동작이 달랐습니다.
게임 28개에 장르 · 인원 · 분위기 · 플레이 시간 태그를 붙이고, 입력한 키워드가 모두 들어간 게임만 후보로 남긴 뒤 그중에서 뽑도록 바꿨습니다.
결과 문구에 "'혼자, 힐링, 짧게' 취향에 맞는 게임 4개 중에서"처럼 후보 수를 함께 보여 주고, 후보가 없으면 다른 키워드를 입력하도록 안내합니다.
취향과 상관없이 뽑고 싶을 때는 뽑기 설정의 체크박스를 선택해 전체 목록에서 뽑습니다.
