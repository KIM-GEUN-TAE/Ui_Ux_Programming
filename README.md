# 겜뽑기

취향만 고르면 오늘 할 게임을 뽑아드립니다.

게임은 많은데 오늘 뭘 할지 정하지 못해 시간을 보내는 게이머를 위한 서비스입니다.
장르·분위기·플레이 시간 같은 취향을 고르면 조건에 맞는 게임 중 하나를 추첨해서 바로 정해줍니다.

## UX 계획

| 항목 | 내용 |
| --- | --- |
| 사용자 | 게임은 많은데 오늘 뭘 할지 정하지 못해 시간을 보내는 게이머 |
| 목적 | 내 취향에 맞는 게임을 고민 없이 빠르게 하나 정한다 |
| 핵심 행동 | 취향 키워드를 입력하고 게임 뽑기 버튼을 누른다 |
| 정보 순서 | 서비스 소개 → 주요 기능 → 이용 방법 → 게임 뽑기 |

## 2주차 · HTML 구조

```
body
├── header
│   ├── h1  겜뽑기
│   ├── p   한 줄 소개
│   └── nav  a ×4 (about · features · steps · pick)
├── main
│   ├── section#about     h2 · h3 · p · img
│   ├── section#features  h2 · ul > li ×3 (h3 · p)
│   ├── section#steps     h2 · ol > li ×3
│   └── section#pick      h2 · form (label · input · button)
└── footer
    └── p  © 2026 겜뽑기
```

## 구현하면서 바꾼 부분과 이유

### 1. 마지막 영역 `#subscribe` → `#pick`(게임 뽑기)

예제 서비스(캠퍼스 마감 알림)의 핵심 행동은 "이메일로 알림 신청"이라 `#subscribe`였지만,
겜뽑기의 핵심 행동은 "취향을 입력하고 게임을 뽑는 것"입니다.
nav 메뉴 이름·section id·h2 제목·버튼 문구가 모두 같은 말이어야 사용자가 이동 결과를
예상할 수 있으므로, 영역 이름을 **게임 뽑기(`#pick`)** 로 통일했습니다.

### 2. 입력 칸을 이메일 대신 취향 키워드로 변경

`type="email"` 입력은 이 서비스에서 사용자가 실제로 해야 하는 행동과 맞지 않습니다.
2주차 범위인 "입력 한 칸 + 버튼"은 유지하면서, 입력 목적을 **취향 키워드**(`type="text"`)로 바꾸고
placeholder에 "예: 혼자, 힐링, 30분"처럼 작성 예시를 넣었습니다.
장르·분위기·플레이 시간을 각각 고르는 여러 입력 항목(`select`, 체크박스 등)은
9주차 폼 실습에서 확장할 예정입니다.

### 3. 주요 기능 순서 · `ul` 선택 이유

취향 고르기 → 랜덤 뽑기 → 뽑은 게임 기록 순으로 적었지만, 순서를 바꿔도 각 기능의 의미가
유지되므로 `ul`(순서 없는 목록)을 사용했습니다.
반대로 이용 방법은 "취향 고르기 → 뽑기 버튼 → 결과 확인"처럼 순서가 바뀌면 이용이 불가능하므로
`ol`(순서 있는 목록)로 작성했습니다.

### 4. 이미지 alt

이미지가 "무엇을 보여주는지"가 아니라 이 위치에서 **전달하려는 의미**를 쓰도록
"혼자·힐링·30분 취향 태그를 고른 뒤 오늘의 게임 추첨 결과 카드가 표시된 겜뽑기 화면"으로 작성했습니다.
현재 이미지는 서비스 화면 시안을 표현한 임시 이미지이며, 이후 실제 화면으로 교체할 예정입니다.
